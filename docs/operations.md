# Dashboard operations

Start PostgreSQL, apply migrations, run `npm run owner:setup`, then start the API, web, and worker using `npm run dev:api`, `npm run dev:web`, and `npm run dev:worker` in separate terminals. Open http://127.0.0.1:5173. The password prompt hides your input; it never creates a default password. Resetting the owner password invalidates all sessions.

The dashboard separates source authorization, successful stream checks, source watermarks, coverage, classification, embeddings, and selected-media processing. Successful ingestion does not prove successful indexing. Null timestamps mean unobserved rather than current. When local vision is enabled after initial setup, prior missing-configuration analysis jobs resume automatically as their original jobs under stream leases. Stage counts include completed history and current backlog; history pages are capped at 50 entries on dedicated screens. Database and media sizes display readable units (the API returns bytes). Source streams list coverage bounds and gaps without source bodies or cursors.

Use Connect or Reauthorize for Gmail, Calendar, Google Photos, and Slack. Disabled connection buttons mean deployment settings are missing. Google consent is a separate operation from creating OAuth client credentials. The browser callback returns to the dashboard after success. Failed consent/exchange returns a redacted error; return to the dashboard and restart authorization. Each source requires its own registered callback URL.

Google Photos selection is manual. Click Choose photos to open the Picker in a new tab, then confirm the selection in Google's page. If the tab is blocked, use the fallback link beside the button. Preparation errors appear beside the button and close the temporary blank tab. The worker polls that specific selection and downloads only selected items. For expired sessions, make a new selection. Counts distinguish selected, downloaded, analyzed, failed, keyword-indexed, classified, and embedded items. Embedding counts use the configured model; an absent model is explicit. See `photos.md` and `local-models.md` for analysis setup. Unconfigured model stages remain observable.

Failed jobs show redacted error codes. Fix the configuration or authorization first, then use Retry. A retry starts a new bounded attempt cycle. Queued/running work in the same stream causes a conflict rather than duplicate execution; wait for that work to finish. An expired Photos selection requires new selection rather than retrying its polling job. Analysis retries restore downloaded state and reuse stored bytes even after Picker expiry. Source/model jobs use separate per-record streams so unconfigured classification cannot block photo import recovery.

Slack app-token entry is password-masked, cleared on submit, encrypted server-side, and never returned by the dashboard. Enable Socket Mode, `connections:write` on the app token, and user subscriptions for message.channels, message.groups, message.im, and message.mpim. Run `npm run worker:slack` separately. The dashboard reports token configuration and observed socket state, received/processed event times, pending inbox age/count, reconciliation, and coverage gaps. Token presence does not verify subscription readiness; observe actual delivery. Reconnection alone does not clear historical gaps. See `slack.md`.

Agent creation requires a name and explicit source checkboxes. Copy the returned credential once and store it privately. Listing clients exposes grants and revocation status without stored credential digests. Revoke removes retrieval access; agent credentials cannot authenticate to dashboard endpoints. See mcp.md for read-only client setup and citation resolution.

Conversation settings expose identifiers/titles rather than source-message bodies. Personal overrides persist and queue reclassification. The rolling rule is override OR at least five owner messages OR at least 10 percent of a nonempty seven-day window. Counts use timestamps in `(evaluation time - seven days, evaluation time]`, exclude tombstones/future messages, and disclose incomplete coverage. Configured classification workers process these generations and preserve historical evidence. Without a configured classifier, the stage remains pending.

Validation: `npm run test:db:isolated` exercises real temporary PostgreSQL storage and permissions. `npm run test:ui` exercises browser controls against mocked API/provider responses. Neither proves live Google/Slack access. Live provider/model checks and final acceptance are recorded separately in the OpenSpec task file.

## Overview and navigation

The dashboard opens at `#/overview`. The sidebar links to Sources (`#/sources`), Job History (`#/logs/jobs`), Failures (`#/logs/failures`), Photo Imports (`#/logs/imports`), and Settings for Connections, Agent Access, and Personal Conversations. On narrow displays, open Navigation to select a screen. Direct links, reload, and browser Back/Forward retain the selected screen and history filters/page position. Operational history is separate from the front page; source-message bodies are not browsable here.

Overview shows the full dataset rather than the current history page: active records exclude tombstones, source counts/shares include zero-record connected sources, and sizes use readable binary units. Database size is physical PostgreSQL storage including media, indexes, and operational tables. Media storage is included in that total; do not add the two figures. Source distribution measures records, not physical bytes per provider.

Classification counts cover active records whose classification matches both the current revision and context version. Personal, background, blocking, update, and unorganized are always shown, including zeros. Labels overlap, so their counts need not sum to the active record total. Records without a current completed classification or terminal unorganized result are pending or stale. Queued/running/failed counts are shown independently for each pipeline stage.

Source freshness distinguishes the last poll attempt, last successful poll, and provider watermark; hover over relative ages for an absolute timestamp. A recent failed attempt does not reset the successful-poll age. Sources exposes stream coverage/gaps and Slack socket delivery, receipt/processing times, inbox lag, and reconciliation independently. Missing timestamps say Not observed. Google Photos explicitly uses manual imports and has no scheduled-poll deadline.

## History and recovery

Each operational history screen fetches at most 50 entries. Previous and Next replace the page; unavailable directions are disabled. Filters select source account, applicable status, and a creation-time window (UTC, inclusive From and exclusive Until). Apply filters resets pagination. Refresh reloads the same position; Newest returns to page one while retaining filters. History pages do not automatically refresh or accumulate rows. Use Refresh to update Photos progress or job status. Overview refreshes every five seconds only while open.

Failures includes failed jobs plus failed/expired import sessions. Retry is available for failed jobs and retains queue locking/deduplication and retry rules. If a retry conflicts, wait for active stream work; its error is displayed without losing page position. Expired Picker selections require choosing photos again in Settings > Connections. Choose photos still opens Picker in a new tab, with a fallback link if blocked, and provides a link to import progress. Agent credentials and personal-conversation settings remain under their Settings screens. Conversation pages also replace batches of up to 50.

History is live rather than a snapshot: retries can remove rows from status-filtered pages. An emptied older page remains at its cursor with return controls. New arrivals do not shift previously fetched cursor pages. Jobs and imports sort by immutable creation time and ID (Failures also uses entry type to break ties). Legacy job creation dates are approximated from the old scheduled time; legacy imports use expiry time because no creation time was recorded. New entries record insertion time.

## Operational API contract

All endpoints require the owner session and return no-store responses. Agent bearer credentials cannot access them. Mutations additionally require the existing CSRF token and same-origin checks.

`GET /api/operations/overview` returns `storage` (`database_bytes`, `media_bytes` decimal strings), `records` (`total`, `deleted`, `pending_stale` numeric counts), `sources` (account/provider/display name, authorization status/environment, active `count`, `last_import_at`), `classifications` (`label`, `count`), `stages` (`stage`, `status`, `count`), `streams` (enabled-stream coverage, check/watermark timestamps, `last_job_status`, redacted error code), and `slack` (connection, coverage, and inbox metrics). It does not include job history rows. Source percentages are computed against `records.total`, with zero for an empty dataset.

`GET /api/operations/jobs` and `GET /api/operations/failures` return `{ "items": [], "next_cursor": null }` for an empty page. Items identify `entry_type` (`job` or `import`), ID, account, immutable `created_at`, stage/status, stream, redacted error code, and job attempt/timing metadata where applicable. They never return job payloads or classification evidence.

`GET /api/photos/imports` returns `{ "imports": [], "next_cursor": null }` for an empty page. Import rows include `created_at`, status, selection expiration, redacted error code, configured-embedding indicator, and the existing per-stage counts. Progress is calculated only for the selected page. Single-session `GET /api/photos/sessions/:id` retains its existing object response. `GET /api/operations/conversations?after=<uuid>` returns up to 50 conversations and an optional next cursor.

All three history endpoints accept `source=<account UUID>`, `status=<applicable status>`, `from=<ISO timestamp>`, `to=<ISO timestamp>`, and opaque `cursor`. Jobs support queued/running/done/failed; imports support selecting/selected/importing/done/failed/expired; Failures supports failed/expired. Invalid filters/cursors and cursors reused with different filters return 400. Use `next_cursor` unchanged with the same filters; the client retains previous cursors for backwards navigation. There is no total page count. A server-side lookahead row determines whether Next exists and is never returned as a 51st entry. Cursor timestamps retain PostgreSQL microsecond precision, including tied-date boundaries.

Deploy the web/API changes together and apply migration `017-operational-history.sql` first using `npm run db:migrate`. The migration adds creation timestamps, legacy backfills, immutability triggers, and ordering/filter indexes. Rollback switches web/API together and may retain those additive database objects; no source content is rewritten or deleted.
