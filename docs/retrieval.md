# Hybrid retrieval

Every current nondeleted record is eligible for indexing, including records with empty text: these receive a deterministic rendering of source kind, external ID, and structured payload. Text is split near paragraph/word boundaries with a 1400 UTF-16-code-unit target and 160-unit overlap. Offsets refer to the immutable `index_sources.content` text. Source titles/body and each derived OCR/description artifact have separate index-source identities. Unicode surrogate pairs are not split.

Chunks and index-source text are never overwritten during a rebuild. Adding derived text appends chunks and preserves older citation IDs. Ordinary queries join only the record's current revision and exclude tombstones immediately, even before replacement chunks exist. Explicit revision/chunk lookup can still resolve historical evidence under the same source grants.

Keyword indexing commits before embedding calls. If the model is absent or fails, keyword/exact retrieval stays available and the embedding job exposes a redacted failure and bounded retries. Embedding identity includes adapter, model, version, and fixed dimension; a mismatched dimension is rejected. Each model/dimension has its own cosine HNSW index. Switching model settings queues missing embeddings into that model's separate index and never compares incompatible vectors.

`search_context` accepts an optional query (up to 2000 characters), filters, limit (1–50), and cursor. Without query text it returns exact-filter matches, even before indexing. With text it fuses up to 500 keyword and 500 semantic candidates with reciprocal rank fusion (constant 60), then deduplicates records. Pagination is bounded to this candidate window; cursors are tied to query/filters and permissions are checked again on every page. Source grants, current revisions, tombstones, and exact filters apply before candidate ranking. Embedding query failure falls back to keyword matching and reports semantic availability as false.

Filters: account_id, provider, kind, external_id, conversation_id, participant (exact identity external ID or email), label, task_status, from (inclusive), to (exclusive), amount, currency, merchant, financial_account_id, pending, posted_date, calendar_date (within an all-day range), calendar_start (exact timestamp). Amount is an exact decimal string, never a JSON floating-point number. Timestamp filters require a timezone; date filters use YYYY-MM-DD. Source-specific filters operate on current typed source details. Invalid/unknown filters fail rather than silently widening a query.

Every returned excerpt has account/source identity, exact record/revision/chunk IDs, source URL or explicit null, source timestamps or explicit null, captured time, and a stable `personal-context://records/{id}/revisions/{id}/chunks/{id}` URI. Generated descriptions are explicitly marked interpretations and retain model/version and derived-content IDs. Keyword/semantic coverage counts and stream freshness are grant-filtered; synchronization time does not assert upstream freshness.

Direct record/revision retrieval supports bounded source body slices using text_offset and text_limit (up to 16000), returning next_offset when more text remains. Chunk lookup verifies record→revision→chunk lineage. Historical retrieval does not reuse current typed metadata as if it described the old revision. Missing and ungranted IDs are indistinguishable at the MCP boundary.

Rebuilds are resumable: the scheduler queues current records missing keyword sources, new derived artifacts, or configured embeddings, under durable stream leases. Existing failed jobs require operator retry after fixing the model. A deliberately new model version queues its separate embeddings. Preserve migrations, original revisions, media, credentials/encryption key, and index sources/chunks in backups so historical chunk citations survive restoration.

Fixture/PostgreSQL checks exercise paraphrases, exact high-precision amounts, stale chunks, historical citation resolution, local-model outage fallback, source-grant filtering, and revocation. These checks do not claim live local inference.

Current results also include typed source details (including exact decimal strings and calendar date/timestamp fields), participants, and explicit classification state. Historical revisions do not attach mutable current typed details. Retrieval runs in a read-only, repeatable-read transaction, so body, metadata, labels and freshness share a consistent snapshot. Classification metadata distinguishes pending, processing, retrying, stale, done, failed and historical states; expired group relevance is not presented as a current label.
